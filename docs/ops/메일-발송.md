# 메일 발송 런북 (SV2)

인증 메일(가입 OTP, 비밀번호 재설정)을 팀 공용 Gmail의 SMTP로 보낸다(2026-11-23 결정, 아키텍처 §0·§3-2).
**앱 비밀번호와 계정 비밀번호는 이 문서에도, 저장소에도, 슬랙에도 쓰지 않는다.**

## 1. 왜 Gmail인가
- 예상 발송량이 하루 100통 이하다. Gmail 한도(하루 약 500통)의 1/5이고, Supabase Auth도 시간당 30통으로 제한한다(§3-2).
- Google 서버에서 보내므로 SPF, DKIM, DMARC가 Google 쪽에서 처리된다. 도메인을 사지 않아도 된다.
- **교체 조건:** 계정이 정지되거나 경고를 받을 때, 하루 300통을 넘을 때, 앱 비밀번호가 막힐 때. 이 경우 Resend와 자체 도메인으로 바꾼다. Supabase SMTP 설정 4칸만 바꾸면 된다.

## 2. 기본 정보
| 항목 | 값 |
|---|---|
| 발신 계정 | `postechdeliverymate@gmail.com` |
| 발신 이름 | `APP_NAME` |
| 소유 | P5. 복구 전화번호와 복구 메일에 팀원 2명 등록 |
| 2단계 인증 | ON (앱 비밀번호를 만들려면 필수) |
| 앱 비밀번호 보관 | 팀 비밀번호 관리자 _(위치만 기록)_ |

> 앱 비밀번호는 반드시 **공용 계정만 로그인된 시크릿 창**에서 만든다. 여러 계정이 로그인된 창에서 만들면 다른 계정에 생겨 `535 BadCredentials`가 난다(2026-11-23 실제로 겪음).

## 3. 진행 순서 (약 20분)
1. **개인 계정이 아닌** 새 Gmail 계정을 만든다. 주소에 `postech`가 들어가므로 발신 이름은 `APP_NAME`으로 두고, 본문에 학교 공식 서비스가 아님을 밝힌다.
2. Google 계정 → 보안 → **2단계 인증** 켜기.
3. Google 계정 → 보안 → **앱 비밀번호**(`myaccount.google.com/apppasswords`) → 이름 `supabase-auth` → 16자리 비밀번호를 비밀번호 관리자에 저장.
4. 아래 4절로 테스트 메일 1통을 POSTECH 주소로 보낸다(Day 2까지).
5. 5절 결과표를 채우고, 받은편지함에 도착하고 세 항목이 pass면 `task.py set SV2 done`.

## 4. 테스트 메일
`curl`로 SMTP 직접 발송. 비밀번호는 셸 변수로만 넣고, 끝나면 터미널을 닫는다.
```bash
read -rs GMAIL_APP_PW   # 붙여넣기, 화면에 안 보임
FROM='postechdeliverymate@gmail.com'; TO='<테스트용 POSTECH 메일>'
SUBJ="=?UTF-8?B?$(printf '[APP_NAME] 인증번호 테스트' | base64)?="   # 한글 제목은 RFC 2047로 인코딩
printf 'From: APP_NAME <%s>\r\nTo: %s\r\nSubject: %s\r\nMIME-Version: 1.0\r\nContent-Type: text/plain; charset=UTF-8\r\nContent-Transfer-Encoding: 8bit\r\n\r\n인증번호: 123456\r\n(POSTECH 공식 서비스가 아닙니다)\r\n' "$FROM" "$TO" "$SUBJ" > /tmp/mail.txt
curl --ssl-reqd --url 'smtps://smtp.gmail.com:465' --user "$FROM:$GMAIL_APP_PW" \
  --mail-from "$FROM" --mail-rcpt "$TO" --upload-file /tmp/mail.txt
unset GMAIL_APP_PW; rm /tmp/mail.txt
```
받은 메일의 원본(헤더)에서 `spf=pass`, `dkim=pass`, `dmarc=pass`를 확인한다.

| 2026-11-23 | 팀원 A | O | 받은편지함 (SCL 1, NSPM) | pass | pass | pass | POSTECH 게이트웨이 1차 검사 기준. Outlook 2차 검사의 SPF softfail은 학교 서버 경유 때문이며 DKIM·DMARC는 pass |

스팸함으로 가면: ① 본문에 링크가 없는지 확인 ② 발신 이름과 제목이 피싱처럼 보이지 않는지 확인 ③ POSTECH 정보통신팀에 발신 주소 허용을 요청한다 ④ 그래도 안 되면 Resend와 도메인으로 바꾼다.

## 6. SV3로 넘기는 값
SV3(P4)가 Supabase Auth → SMTP Settings에 넣는다.

| 설정 | 값 |
|---|---|
| Host / Port | `smtp.gmail.com` / `465` |
| Username | `postechdeliverymate@gmail.com` (전체 주소) |
| Password | 앱 비밀번호. P5가 Supabase 대시보드에 직접 넣는다. 전달이 필요하면 비밀번호 관리자 공유로만 한다 |
| Sender email / name | `postechdeliverymate@gmail.com` / `APP_NAME` |

Sender email은 Username과 같아야 한다. 다르면 Gmail이 발신 주소를 계정 주소로 바꿔 버린다.

## 7. 운영 점검
- 주 1회 Gmail 보낸편지함과 보안 알림을 확인한다(정지 경고, 반송).
- 앱 비밀번호는 담당자가 바뀌거나 유출이 의심되면 즉시 폐기하고 다시 만든다.
