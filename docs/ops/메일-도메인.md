# 메일 발송 도메인 런북 (SV2)

인증 메일(가입 OTP, 비밀번호 재설정)을 보내는 도메인과 Resend 설정을 기록한다.
기준 명세: 아키텍처 §0(메일 발송), §3-2(Auth 설정값). **API 키, SMTP 비밀번호는 이 문서에 쓰지 않는다.**

> 도메인은 아직 임시 값 `example.kr`이다. 실제 도메인이 정해지면 이 문서, 아키텍처 §0·§3-2, CLAUDE.md "현재 상태"의 `example.kr`을 한 PR에서 바꾼다.

## 1. 기본 정보
| 항목 | 값 |
|---|---|
| 루트 도메인 | `example.kr` (임시) |
| 발신 서브도메인 | `mail.example.kr` |
| 발신 주소 / 이름 | `no-reply@mail.example.kr` / `APP_NAME` |
| 구매처 · 갱신일 | _(구매 후 기록)_ |
| DNS 관리 위치 | _(구매처 DNS 또는 Cloudflare)_ |
| Resend 리전 | Tokyo (`ap-northeast-1`), 서울 Supabase와 가장 가깝다 |
| Resend 계정 소유 | P5 (팀 공용 메일로 가입, 팀원 초대) |

서브도메인(`mail.`)으로 보내는 이유: 루트 도메인의 평판과 분리하고, 나중에 웹(`web/**`)·딥링크용 루트 도메인 설정과 레코드가 겹치지 않게 한다.

## 2. 진행 순서
1. **도메인 구매**: `.kr`은 가비아·후이즈 등에서 산다. 개인 명의도 된다(약관·스토어 등록 시 운영자 정보와 맞춘다).
2. **Resend 도메인 추가**: Resend → Domains → Add Domain → `mail.example.kr`, Region `Tokyo`.
3. **DNS 레코드 입력**: Resend 화면에 나온 값을 아래 표 형식대로 DNS 콘솔에 넣는다. 값은 Resend가 발급한 것을 그대로 복사한다.
4. **전파 확인**: `docs/ops/check-mail-dns.sh example.kr` 실행. 모두 OK가 나오면 Resend에서 **Verify DNS Records**를 누른다.
5. **테스트 발송**(Day 2까지): 3절 방법으로 POSTECH 메일에 1통 보낸다.
6. 결과를 4절에 기록하고, Verified가 되면 `task.py set SV2 done`.

## 3. DNS 레코드
DNS 콘솔에서 호스트 이름은 보통 루트 도메인을 뺀 부분만 적는다(예: `send.mail`). 콘솔이 전체 이름을 요구하면 `send.mail.example.kr`처럼 적는다.

| 용도 | 타입 | 호스트 | 값 | 우선순위 |
|---|---|---|---|---|
| SPF(반송 경로) | MX | `send.mail` | `feedback-smtp.ap-northeast-1.amazonses.com` | 10 |
| SPF | TXT | `send.mail` | `"v=spf1 include:amazonses.com ~all"` | |
| DKIM | TXT | `resend._domainkey.mail` | `p=MIGfMA0…` _(Resend가 발급한 긴 값 그대로)_ | |
| DMARC | TXT | `_dmarc` | `"v=DMARC1; p=none; rua=mailto:dmarc@example.kr"` | |

- 위 MX·SPF 값은 Tokyo 리전 기준 예시다. **Resend 화면에 나온 값이 기준**이다.
- DMARC는 루트(`_dmarc.example.kr`)에 두면 `mail.` 서브도메인에도 적용된다. 처음에는 `p=none`으로 두고, 출시 후 보고서에 문제가 없으면 `p=quarantine`으로 올린다(SV10 보안 점검 때 검토).
- `rua` 주소를 받을 메일함이 없으면 `rua=` 부분을 빼도 된다.
- 루트 도메인에 이미 SPF TXT가 있어도 상관없다. Resend SPF는 `send.mail` 호스트에만 둔다.

### 전파 확인
```bash
docs/ops/check-mail-dns.sh example.kr
# 또는 직접
dig +short MX  send.mail.example.kr
dig +short TXT send.mail.example.kr
dig +short TXT resend._domainkey.mail.example.kr
dig +short TXT _dmarc.example.kr
```
`.kr`은 보통 수 분에서 몇 시간 안에 전파된다. 24시간이 지나도 안 보이면 호스트 이름에 루트 도메인이 두 번 붙지 않았는지(`send.mail.example.kr.example.kr`) 확인한다.

## 4. 테스트 메일
Resend 대시보드 → Emails → Send test email, 또는:
```bash
# RESEND_API_KEY는 셸에서만 설정한다. 파일에 저장하거나 커밋하지 않는다.
curl -s https://api.resend.com/emails \
  -H "Authorization: Bearer $RESEND_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"from":"APP_NAME <no-reply@mail.example.kr>","to":["<테스트용 POSTECH 메일>"],"subject":"[APP_NAME] 인증번호 테스트","text":"인증번호: 123456"}'
```
받은 메일에서 원본 보기(헤더)를 열어 `spf=pass`, `dkim=pass`, `dmarc=pass`를 확인한다.

### 결과 기록
| 날짜 | 받는 주소(앞부분만) | 도착 | 받은편지함/스팸 | SPF | DKIM | DMARC | 비고 |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

스팸함으로 가면: ① 세 항목이 모두 pass인지 확인 ② 제목·본문에 링크나 과한 문구가 없는지 확인 ③ POSTECH 정보통신팀에 발신 도메인 허용(화이트리스트)을 요청한다.

## 5. SV3로 넘기는 값
SV3(P4)가 Supabase Auth → SMTP Settings에 넣는다. 아키텍처 §3-2를 따른다.

| 설정 | 값 |
|---|---|
| Host / Port | `smtp.resend.com` / `465` |
| Username | `resend` |
| Password | Resend API 키(**Sending access만**, 도메인 `mail.example.kr`로 제한). P5가 만들어 Supabase 대시보드에 직접 넣거나 1Password 등으로 전달한다. 슬랙·깃허브에 붙이지 않는다 |
| Sender email / name | `no-reply@mail.example.kr` / `APP_NAME` |

## 6. 완료 기준

- [ ] SPF·DKIM·DMARC 레코드 입력, `check-mail-dns.sh` 모두 OK
- [ ] Resend 대시보드에서 도메인 **Verified**
- [ ] POSTECH 메일로 테스트 1통 도착, 받은편지함 여부 기록
